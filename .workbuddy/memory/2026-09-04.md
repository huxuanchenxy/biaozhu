## 环境坑：Vite 缓存目录删除失败导致 dev 起不来

- 现象：`npm install` 后首次 `vite` 报 `[safe-delete] 操作失败 ... node_modules\.vite\deps`
- 原因：Vite 要删 `node_modules/.vite/deps` 重建预构建缓存，沙箱的 safe-delete shim（genie-trash）对该路径失败
- 解决：`mv node_modules/.vite node_modules/.vite_bak_<时间戳>` 改名绕过（不要用 rm），Vite 会重新生成
- 同样的坑也在 `vite build` 清空 `dist/assets` 时出现 → 先 `mv dist dist_bak_<时间戳>` 再 build
- dev server 用后台任务 kill 后端口不一定释放，再启动会报 `Port already in use`；用 PowerShell
  `Get-NetTCPConnection -LocalPort <port> -State Listen | Select -ExpandProperty OwningProcess | Stop-Process -Force`
- **新增坑（装 @huggingface/transformers 后）**：Vite 预打包该包会生成 302 文件的 `.vite/deps_temp_*`，
  commit 时 safe-delete 因「>50 文件需确认」直接抛错杀掉 dev 进程（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`）
  → 解决：在 `vite.config.ts` 加 `optimizeDeps: { exclude: ['@huggingface/transformers','onnxruntime-web'] }`，
  浏览器按原生 ESM 加载该包（生产构建走 Rollup 不受影响）。注意改 vite.config 后需重启 dev。

## 翻译后端切换到 transformers.js 自托管（去掉用户下载手势）

- 决策：用户不喜欢浏览器 Translator API「首次需点击下载语言包」的手势限制；确认改用 `@huggingface/transformers` v4（NLLB-200-distilled-600M）自托管，**任何浏览器可用、200 语言、用户无下载手势**
- 关键澄清（纠正之前表述）：
  - `npm run build` **不会**下载模型；模型权重（~600MB 量化 onnx）在**用户浏览器首次调用 pipeline() 时**拉取 → 故必须自托管
  - 「慢」是**用户用时**的推理速度（WASM 慢 / WebGPU 快），不是 build 期
  - transformers.js **无 Chrome 手势限制**；只要 `env.allowRemoteModels=false` + `env.localModelPath='/models/'` 自托管，模型随页面作为静态资源下发，用户只看到进度条
- 新增/改动文件：
  - `scripts/download-model.mjs` + `package.json` 加 `fetch:model`：从 HF Hub 拉 NLLB 权重到 `public/models/Xenova/nllb-200-distilled-600M/`（gitignore 已加 public/models、public/wasm）
  - `src/workers/translation.worker.ts`：Worker 内 `pipeline('translation', MODEL_ID, {device:'webgpu'→降级'wasm', dtype:'q8', progress_callback})`；`env.allowRemoteModels=false` + `localModelPath='/models/'`
  - `src/utils/translator.ts`：删浏览器 Translator 逻辑；`TranslationEngine` 管理 Worker（ready/translate/进度/错误回调）；`BCP47_TO_NLLB` 映射（fra_Latn/zho_Hans 等）；`detectLanguage` 保留用浏览器 LanguageDetector（Chrome/Edge 才有，Firefox/Safari 降级手动选）；`SOURCE_LANG_OPTIONS`/`TARGET_NLLB='zho_Hans'`
  - `src/components/MarkdownTranslation.vue`：去掉 need-gesture/「开始翻译」按钮；进入即后台加载+翻译，状态栏显示「加载翻译模型 X%」「翻译中 done/total」；源语言下拉值为 NLLB 码；引擎存非响应式 `let`（避 ref 的 UnwrapRef 剥私有字段）；`onBeforeUnmount` destroy 释放 Worker/模型显存
- onnxruntime-web 的 wasm：**Vite build 自动 emit 到 dist/assets**（23MB），随本服务器下发，不访问 CDN；故 worker 不设 wasmPaths
- 验证：`vue-tsc -b` 通过；`vite build` 通过（worker chunk 534KB + ort wasm 23MB）；dev 3010 各资源 200
- **沙箱限制**：HF Hub 在此环境不可达（timeout），无法在此拉 600MB 模型；用户需在本机（有外网）跑一次 `npm run fetch:model` 后翻译才可用；模型缺失时 UI 显示「no-model」提示而非崩溃
- **transformers.js v4.2.0 env 默认值变化**：v3 是 `allowRemoteModels` 一刀切（false 即走本地）；v4 拆成两个开关，`env.allowLocalModels: !(IS_BROWSER_ENV || IS_WEBWORKER_ENV || IS_DENO_WEB_RUNTIME)` → **浏览器/Worker 下默认 `false`**。要做"纯本地加载"必须显式 `env.allowLocalModels = true`，否则 worker 里 pipeline 直接跳过本地分支、又因为 `allowRemoteModels=false` 抛 "attempted to load a remote file" → 被 onError 的 `/not found/i` 规则捕获误判为 no-model。修正后 `src/workers/translation.worker.ts` 同时设 `allowRemoteModels=false; allowLocalModels=true; localModelPath='/models/'`。
